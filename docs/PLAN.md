## Где мы сейчас

Milestone 1 (пилот, $200) собран: живой каталог на всех 737 активных товарах
FashionGo, фильтры, клиентские ссылки, Chrome-расширение с импортом. Осталась
публикация на Cloudflare.

## Что уже сделано

- **Каталог**: Next.js 16 + shadcn/ui, деплой как Cloudflare Worker через
  `@opennextjs/cloudflare`. Сетка карточек, галерея фото, свотчи цветов,
  фильтр по категориям, бейдж New (товары младше 30 дней), «Copy to order».
- **Данные**: весь активный каталог аккаунта itoo (775 карточек, 737 после
  схлопывания перезалитых стилей) вытянут `app/scripts/pull-seed.mjs` и лежит в
  `app/src/data/fashiongo-seed.json` (1.6 МБ). Цена = цена FashionGo минус $1.
  У каждого товара есть ряд размеров, разбивка упаковки и минимальный заказ.
- **Админ/клиент**: переключатель без авторизации (заглушка, как договорились).
  В админ-виде: чекбоксы на карточках → «Copy link» собирает ссылку с выбранными
  товарами. Клиентская ссылка открывается сразу в клиентском виде.
- **Превью в мессенджерах**: OG-теги рендерятся на сервере, ссылка
  разворачивается в карточку с фото товара.
- **Синхронизация**: расширение читает токен из `localStorage` открытой сессии
  vendoradmin, тянет товары и шлёт сырой JSON в `/api/sync`; маппинг делается на
  сервере (один протестированный экземпляр кода). Полная перезапись каталога,
  без merge и разрешения конфликтов, как и договаривались для пилота.
- **Тесты**: 216 тестов (Vitest + Testing Library), включая прогон на реальных
  данных FashionGo и тесты интерфейса.

## Что осталось для сдачи M1

1. Опубликовать на Cloudflare Workers (нужен API-токен или подключение репо в
   дашборде: root `app`, build `npx opennextjs-cloudflare build`, deploy
   `npx opennextjs-cloudflare deploy`).

   несколько → ссылка клиенту.

## Источник данных: официальное API FashionGo

**Решение от 04.08.2026: работаем через их публичное REST API, доступ к панели
вендора отключён в коде.**

У FashionGo есть документированное API по адресу
`https://pubapi.fashiongo.net/api.html`, методы `GET /v1.0/items` и
`GET /v1.0/items/{itemId}`, авторизация по API-ключу. Поддержка отвечала на узко
заданный вопрос («выгрузить весь каталог одним махом вместе с картинками»),
поэтому ответ был «нет». Но постраничное чтение своих же товаров там есть, и с
версии 1.0.23 `imageUrl` отдаёт **оригинал** фотографии, а не превью. Этого
хватает для каталога полностью.

Их Terms of Use прямо запрещают «use any robot, spider, scraper or other
automated means to access the Site for any purpose», и `vendoradmin.fashiongo.net`
там назван частью Site. Поэтому путь через панель выключен: `login()` в
`app/scripts/fashiongo-client.mjs` и импорт в расширении не работают без явного
флага. Ключ к API запрашивает клиент у поддержки: экрана самостоятельной выдачи
в панели нет, но есть страница API Terms of Use, то есть процесс у них штатный.

### Что было выяснено о структуре их данных (остаётся в силе)

Разбор полей ниже сделан на данных, полученных до перехода на API, и описывает
то же самое, что отдаёт `GET /v1.0/items`:

- `GET /api/crypto/key?default=false` → RSA-ключ.
- Пароль шифруется AES-256-CBC случайным 32-символьным hex-ключом (IV берётся из
  первых 16 символов), сам ключ шифруется RSA PKCS#1 v1.5 → `POST
  https://id.fashiongo.net/api/auth/login` → JWT (~30 дней).
  **Грабли:** экспонента приходит как `10001`, то есть нечётной длины, и
  `Buffer.from(hex)` молча режет её; нужен паддинг нулём.
- `GET /api/items?pn=1&ps=20&saleType=W&pageType=1` отдаёт список (775 активных).
  `ps` принимает только значения из их набора: 20 работает, 10 и 24 отклоняются.
- `GET /api/item/{id}` отдаёт карточку; **реальные цвета и галерея лежат в
  `image[]`** (массивы `color`/`size`/`pack` в корне задают справочники, а не
  значения товара).
- **Размеры и упаковка.** У товара только `sizeId` и `packId`, а значения ищутся
  в справочниках из той же карточки. `sizeDescription2` = ряд размеров через `;`
  («S;M;L»), `packDescription` = разбивка через `-` («2-2-2»), позиции совпадают
  один в один; сумма = минимальный заказ (`item.minTQStyle`). `packId` 0/null
  означает, что товар продаётся россыпью и минимум задан только числом. В именах
  `sizeName`/`packName` лежит свободный текст, у части записей там мусор; админка
  сама читает описания, и мы тоже.
- **Даты.** В списке товаров админка показывает `_activatedOn` и от него же
  считает свой бейдж «new»; `_createdOn` («Upload Date» в их сортировке) хранит
  дату загрузки, у отлежавшегося черновика она на недели раньше. Каталог датирует
  товар по `_activatedOn`.
- **Один стиль может быть залит несколько раз.** 37 номеров из 775 активных
  повторяются (перезаливка). Каталог схлопывает их, оставляя свежую карточку.
- `GET /api/misc/categories` отдаёт имена категорий с количеством: `"Tops (299) "`.
  У товара `categoryId` указывает на подкатегорию; человеческое имя даёт
  `parentCategoryId` из карточки.
- Картинки: `fg-image.fashiongo.net`, варианты `/list/` и `/large/`, отдаются
  публично без авторизации и реферера, так что хотлинк работает.
- Токен админки лежит в `localStorage.token`.

## Договорённости по продукту (с созвона 03.08.2026)

- FashionGo остаётся единственным источником правды, каталог зеркалит 1:1.
- Цена каталога = цена FashionGo − $1.
- Фильтр по категориям + возможность собрать выборку из разных категорий.
- Любой товар можно скрыть вручную (распродан).
- Клиент получает короткую ссылку: конкретные товары или категория целиком.
- «New arrivals» считаются автоматически: товары младше 30 дней по дате
  публикации в FashionGo (`_activatedOn`, её же показывает их админка). Сейчас
  таких 38 из 737.
